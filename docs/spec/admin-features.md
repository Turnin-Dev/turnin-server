# 개요

- 운영자 기능은 필요한 기능을 모아 한꺼번에 구현한다.
- 현재 신고 검토와 게시물 숨김은 운영자가 DB에서 직접 처리한다.
- 이 문서는 확정 명세가 아닌 예상 기능 목록이며, 구현 시점에 상세 명세로 옮긴다.

### 기존 운영자 기능

- 공지사항 생성, 상태 변경, 삭제 (`AnnouncementAdminRoutes`, Swagger: `/swagger/admin`)

# 예상 기능 목록

- **[게시물 숨김/복구]**
    - 신고를 검토한 뒤 게시물 (사용자 키워드)을 비활성화 (`is_active = false`)하거나, 신고 대상이 아니라고 판단되면 다시 활성화한다.
    - 운영자 비활성화는 복구 가능성이 있으므로 핑퐁을 삭제하지 않는다. (핑퐁 삭제는 사용자 행위 유스케이스에서만 수행)
    - **구분 필요:** 현재 `is_active = false`는 아래 세 경우를 모두 포함하므로, 복구 시 운영자가 숨긴 게시물만 골라낼 수 있어야 한다.
        - 운영자가 숨긴 게시물 → 복구 대상
        - 작성자가 직접 삭제한 신고된 게시물 (Soft Delete, 핑퐁은 이미 삭제됨) → 복구하면 안 됨
        - 탈퇴한 사용자의 신고된 게시물 → 복구하면 안 됨 (사용자 `is_active`로 구분 가능)
    - 두 번째 경우는 `is_active`만으로 구분할 수 없으므로, 운영자 숨김 또는 작성자 삭제 중 하나를 표시하는 컬럼 (예: `hidden_at` 또는 `deleted_at`) 추가를 검토한다.
- **[신고 목록 조회]**
    - 게시물/사용자 신고 (`report`)와 콘텐츠 신고 (`content_report`, 신고 시점 스냅샷 포함) 조회.
- **[자동 숨김 콘텐츠 검토/복구]**
    - 신고 누적 (5회)으로 자동 숨김 처리된 핑퐁 질문/답변 (`question_hidden_at`, `hidden_at`)을 검토하고, 신고 대상이 아니면 숨김을 해제한다.
