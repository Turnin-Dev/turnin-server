# 개요 및 요구사항

### 목적/배경

- 소통 기능의 부재로 사용자 간 소통 창구가 없었음.
- 타인의 평가 및 시선이 강하게 느껴지는 기존 댓글 방식과는 다른 소통 방식이 필요했음.
- 소통과 동시에 나에 대해 좀 더 생각할 수 있도록 의도되어야함.

### 핵심 요구사항

- 사용자가 게시물 하단에 ‘핑퐁’을 작성하고 조회할 수 있어야 함.
- 도배 방지를 위한 글자 수 및 작성 연사 제한 필요.
- 핑퐁은 질문자 (Q)와 게시물 작성자 (A)의 1:1 대화 형태로 구성되며, 답변은 게시물 작성자만 작성할 수 있음.
- 질문 등록 시 게시물 작성자에게, 답변 등록 시 질문자에게 알림이 발송되어야 함.
- 부적절한 내용에 대한 삭제/신고 기능이 있어야 함.
- 차단 관계 (양방향)인 사용자 간에는 핑퐁으로 상호작용할 수 없어야 하며, 차단 전에 달린 핑퐁은 각 사용자가 직접 관리함.

### 1차 범위 제약

- 핑퐁 내 대댓글 (꼬리질문)은 미지원, 1질문-1답변 구조만 지원.
- 텍스트만 지원하며, 이미지/파일 첨부는 미지원.
- 등록된 질문/답변은 수정 불가하며 삭제만 가능.
- 전체 공개/비공개 여부 중 1차에서는 기본 전체 공개로 한정.
- 1차에서는 미답변 질문 리스트 별도 확인 불가. (게시물에서만 직접 확인 가능)

# 상세 기능 명세

- **[핑퐁 작성]**
    - 게시물 하단에 질문 입력 영역을 노출하며, 최대 글자 수는 2,200자로 제한.
    - 동일 사용자가 동일 게시물에 연속 작성 시 5초당 1회/1분당 5회 작성 간격 제한 적용.
    - 게시물 작성자 본인의 글에 질문을 작성할 수 없다.
- **[핑퐁 답변]**
    - 게시물 작성자에게만 답변 작성 권한 부여.
- **[핑퐁 조회]**
    - 게시물 하단에 리스트 형태로 노출, 최신순 정렬
    - 커서 기반 페이지네이션으로 조회 (페이지 크기 1~25).
    - 질문자 정보 (이름, 프로필 사진)를 함께 노출.
    - 신고 누적으로 숨김 처리된 질문은 목록에서 제외. 답변만 숨김 처리된 경우 질문은 노출하고 답변은 노출하지 않음.
    - 탈퇴한 사용자의 핑퐁 (남긴 질문, 본인 게시물에 달린 핑퐁)은 탈퇴 즉시 삭제되므로 목록에 노출되지 않음.
- **[핑퐁 삭제/신고]**
    - 질문자는 본인 질문을, 게시물 작성자는 본인 답변과 질문 자체를 삭제 가능 (단, 질문 삭제시 연결된 답변도 함께 삭제).
    - 부적절한 질문/답변에 대한 신고 기능 제공, 신고 시 운영 정책에 따라 노출 제한.
    - 신고 운영 정책: 5회 신고 누적 시 숨김 처리.
    - 질문 삭제와 답변 삭제는 별도 API로 제공하며, 답변 삭제 시 질문은 유지되고 다시 답변할 수 있음.
    - 신고는 핑퐁 전용이 아닌 콘텐츠 신고 (`contentReport`) 기능으로 제공하며, 신고 시점의 콘텐츠 내용을 스냅샷으로 보관.
    - 동일 사용자는 동일 콘텐츠를 한 번만 신고할 수 있으며, 본인이 작성한 콘텐츠는 신고할 수 없음.
    - 질문이 숨김 처리되면 핑퐁 전체가, 답변이 숨김 처리되면 답변만 목록에서 제외.
    - 숨김 처리된 질문/답변은 삭제/신고 대상에서 제외. (존재하지 않는 것으로 처리)
- **[차단 정책]**
    - 차단 관계 (양방향)인 사용자의 게시물은 조회할 수 없으므로, 해당 게시물의 핑퐁 목록 조회 및 질문 작성 불가.
    - 차단 전에 달린 핑퐁 (질문/답변)은 자동으로 삭제하지 않으며, 각 사용자가 직접 삭제/신고하여 관리.
    - 게시물 작성자는 차단 전에 달린 질문을 관리할 수 있도록 차단 관계 질문자의 질문도 조회 가능. 그 외 사용자에게는 본인과 차단 관계인 질문자의 핑퐁이 노출되지 않음.
    - 게시물 작성자는 차단 관계 질문자의 질문에 답변할 수 없음. (차단 방향은 노출하지 않음)
- **[알림]**
    - 질문 등록 시 게시물 작성자에게 알림 발송.
    - 답변 등록 시 질문자에게 알림 전송.

# 기술 명세 및 참고

- **API / DB:**
    - API:
        - `POST /user-keyword/{userKeywordId}/ping-pong` - 질문 등록
        - `POST /ping-pong/{pingPongId}/answer` - 답변 등록
        - `GET /user-keyword/{userKeywordId}/ping-pong` - 핑퐁 목록 조회
        - `DELETE /ping-pong/{pingPongId}` - 질문 삭제 (연결된 답변 함께 삭제)
        - `DELETE /ping-pong/{pingPongId}/answer` - 답변 삭제
        - `POST /content-report` - 콘텐츠 (질문/답변) 신고 (`contentType`: `PING_PONG_QUESTION` | `PING_PONG_ANSWER`)
    - DB Table:
        - `ping_pong` (기존 comment 테이블과 컬럼 구조가 유사하지만, 질문/답변 상태 (status), 답변자 제한 로직이 다르므로 별도 테이블로 분리 권장)
        - `content_report` (핑퐁만을 위한 테이블은 아니며 특정 컨텐츠 신고 시 해당 내용을 스냅샷 찍어 함께 보관하는 용도의 추가 신고 테이블)
