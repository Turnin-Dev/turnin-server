# 개정 이력

- (날짜) | 최초 작성 (V1)
- (날짜) | 개수 제한 이유 변경, 조회 시 키워드 내용 함께 조회, 삭제 시 핑퐁 삭제 정책 추가 (V2)
- (날짜) | 문서 목차 정리, 신고된 게시물 삭제 후 1년 파기 정책 추가

# 개요 및 요구사항

### 목적/배경

- 사용자가 자신을 표현하는 `키워드`와 그에 대한 내용을 게시물 (사용자 키워드)로 등록할 수 있어야 함.
- 나에 대해 정말 중요한 키워드만 등록하도록 개수를 제한함.

### 핵심 요구사항

- 사용자는 키워드를 생성, 조회, 수정, 삭제할 수 있어야 함.
- 키워드 길이와 사용자당 키워드 개수에 제한이 있어야 함.
- 게시물을 삭제하면 게시물에 달린 핑퐁은 신고 여부와 관계없이 함께 삭제되어야 함.
- 신고된 게시물은 신고 데이터와의 연계를 위해 삭제 후에도 일정 기간 격리 보관 후 파기해야 함.

### 1차 범위 제약

- 키워드 내용의 글자 수 제한은 없음.
- 키워드 자체는 수정할 수 없으며, 변경하려면 삭제 후 새로 생성해야 함.
- 운영자의 게시물 숨김/복구는 별도 기능으로 분리. ([admin-features.md](rq-32admin-features.md))

# 상세 기능 명세

- **[생성]**
    - 사용자는 키워드와 키워드에 대한 내용을 입력해 게시물을 생성할 수 있음.
    - 키워드 길이는 1~15자로 제한.
    - 사용자 1명당 키워드는 최대 5개까지 등록 가능.
        - 제한 이유: 나에 대한 정말 중요한 키워드만 등록하기 위해, 서버 리소스 절약
    - 동일 사용자는 같은 키워드를 중복으로 등록할 수 없음.
- **[조회]**
    - 사용자는 본인 키워드를 키워드 내용과 함께 조회할 수 있음.
    - 비활성화된 게시물 (삭제/숨김 처리)은 조회되지 않음.
- **[수정]**
    - 사용자는 본인 키워드의 `키워드에 대한 내용`만 수정할 수 있음.
- **[삭제]**
    - 사용자는 본인 키워드를 삭제할 수 있음.
    - 게시물에 달린 핑퐁 (질문/답변)은 신고 여부와 관계없이 함께 삭제됨.
    - 신고 내역이 없는 게시물은 즉시 삭제됨.
    - 신고 내역이 있는 게시물은 비활성화되어 사용자에게 노출되지 않고, 삭제 시각을 기록해 1년간 격리 보관 후 신고 내역과 함께 파기됨. **(파기 구현 예정)**
    - 계정 탈퇴 시 게시물 처리는 [account-deletion.md](rq-3-account-deletion.md)를 따름.

# 기술 명세 및 참고

- **API / DB:**
    - API:
        - `POST /user-keyword` - 게시물 생성 (생성 요청 수 제한 적용)
        - `GET /user-keyword` - 게시물 목록 조회
        - `GET /user-keyword/{userKeywordId}` - 게시물 상세 조회
        - `PATCH /user-keyword` - 키워드 내용 수정
        - `DELETE /user-keyword?userKeywordId={id}` - 게시물 삭제 (성공 204, 대상 없음 404)
    - DB Table:
        - `user_keyword`
            - `is_active`: `false`면 비노출 (작성자 삭제 중 신고된 게시물, 탈퇴, 운영자 숨김)
            - `deleted_at`: 작성자 쪽 사유 (직접 삭제, 계정 탈퇴)로 삭제된 시각. 운영자 숨김과 구분하는 기준 **(추가 예정)**
            - `uq_user_id_keyword_id`: 사용자별 키워드 중복 등록 방지
    - 삭제 처리 (`DeleteUserKeywordUseCase`, 하나의 트랜잭션):
        - 신고 내역 없음: 게시물 삭제, 핑퐁은 FK `ON DELETE CASCADE`로 함께 삭제.
        - 신고 내역 있음: `report.reported_user_keyword_id`가 `ON DELETE RESTRICT`이므로 삭제할 수 없어, 비활성화 + `deleted_at` 기록 **(추가 예정)** 후 핑퐁을 명시적으로 삭제.
        - 핑퐁 삭제는 유스케이스에서만 수행하고, 리포지토리의 비활성화 메서드에 두지 않음. (운영자 숨김 시 핑퐁 유지)
    - 파기 배치 **(구현 예정)**:
        - `deleted_at`이 1년 지난 게시물의 신고 행을 먼저 삭제한 뒤 게시물을 삭제.
        - 계정 삭제 배치와 같은 작업 안에서 계정 삭제 배치보다 먼저 실행해 동시 실행을 방지.
